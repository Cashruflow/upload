# ТЗ: ИИ-помощник по платформе в модальном окне

Платформа: ai.cashruflow.ru (бэклог задач, CRM, кабинеты клиентов, медкарта, SEO).
Задача: встроить в платформу чат-виджет, в котором клиент задаёт вопросы ИИ о платформе
и получает ответ: где находится нужная функция и что там поправить.

Ориентир по внешнему виду: виртуальный помощник партнёрской программы Trip.com.

---

## 1. Что должен получить клиент

- Кнопка-иконка чата в правом нижнем углу на любой странице кабинета.
- По клику открывается окно чата поверх страницы (страница под ним остаётся рабочей).
- Клиент пишет вопрос обычным языком: «где поменять реквизиты?», «как добавить задачу в бэклог?».
- ИИ отвечает коротко, по-русски, с путём в интерфейсе (`Настройки → Реквизиты`) и, если есть,
  со ссылкой прямо на нужную страницу платформы.
- Под каждым ответом кнопки 👍 / 👎 — для оценки качества.
- История диалога сохраняется: закрыл окно, открыл снова — переписка на месте.

## 2. Внешний вид (ПК)

| Элемент | Параметры |
|---|---|
| Окно | фиксировано справа снизу, ширина 360px по умолчанию, тянется мышью за левый край (от 320 до ~600px), высота до ~80% экрана, скругления, тень |
| Шапка | аватар помощника, заголовок «Помощник cashruflow», подзаголовок «Виртуальный помощник», кнопка «свернуть» (шеврон вниз) |
| Лента | сообщения клиента справа (тёмный фон `#455873`, белый текст), ответы ИИ слева (светлый фон `#F5F7FA`, тёмный текст `#0F294D`), небольшие «хвостики» у пузырей, отступ между сообщениями 12px |
| Ответ ИИ | поддержка форматирования: абзацы, **жирный**, списки, ссылки; под ответом разделитель и кнопки 👍 / 👎 |
| Прокрутка | при длинной ленте появляется кнопка «вниз» для быстрого перехода к последнему сообщению |
| Поле ввода | textarea с плейсхолдером «Спросите что угодно о платформе», растёт по высоте от 1 строки (22px) до 8 строк (176px), круглая кнопка отправки; Enter — отправить, Shift+Enter — новая строка |
| Состояния | «ИИ печатает…» во время генерации, ответ появляется потоково (по мере генерации), сообщение об ошибке с кнопкой «повторить» |

**Мобильная версия:** окно открывается на весь экран, ресайза нет.

Цвета и размеры брать из `docs/DESIGN-TOKENS.md` платформы, значения выше — ориентир.

## 3. Архитектура

```
[Браузер: виджет]  --POST /api/assistant/chat (стрим)-->  [Бэкенд платформы]
                                                              |
                                        1. проверка авторизации клиента
                                        2. поиск по базе знаний о платформе
                                        3. сборка промпта: правила + найденные фрагменты
                                           + страница, на которой сейчас клиент
                                        4. запрос к LLM (стрим)
                                        5. сохранение диалога в БД
                                              |
                                        [LLM API]
```

### 3.1. Фронтенд
- Отдельный модуль/скрипт виджета, подключается один раз в общем шаблоне кабинета.
- Не зависит от разметки страниц; все стили изолированы (свой префикс классов, например `cf-chat-`).
- Вместе с вопросом отправляет контекст: текущий URL/раздел платформы, id диалога.
- Состояние «окно открыто/свёрнуто» и ширину окна помнит в `localStorage`.

### 3.2. Бэкенд
- `POST /api/assistant/chat` — принять вопрос, вернуть ответ потоком (SSE).
- `GET /api/assistant/history` — история диалога текущего клиента.
- `POST /api/assistant/feedback` — оценка 👍/👎 по id сообщения (+ необязательный комментарий).
- Ключ LLM хранится только на сервере, в браузер не попадает.
- Ограничение частоты запросов на клиента (например, 20 вопросов в 10 минут).

### 3.3. База знаний о платформе
Главное для качества ответов. Источник — описание платформы «что где лежит»:
- карта разделов: название → URL → что там можно сделать и изменить;
- короткие инструкции «как сделать X» (по шагам, с путём в меню);
- FAQ по частым вопросам клиентов.

Хранить в markdown-файлах в репозитории (например, `docs/help/*.md`), при изменении —
переиндексировать. Для поиска: на старте хватит полнотекстового поиска в БД; позже —
векторный поиск по фрагментам.

### 3.4. Промпт помощника (правила)
- Отвечать только на русском, коротко, по делу.
- Отвечать только по базе знаний о платформе; если ответа нет — честно сказать и предложить
  написать в поддержку, ничего не выдумывать.
- Всегда указывать путь в интерфейсе и ссылку на раздел, если она есть в базе знаний.
- Учитывать страницу, с которой задан вопрос.
- Не раскрывать данные других клиентов; для вопросов о чужих данных — отказ.

**Важно (ошибка из примера Trip.com):** их бот показывает клиенту свои внутренние рассуждения
на английском перед ответом. У нас клиент должен видеть только финальный ответ:
- не выводить в чат блоки рассуждений модели (thinking/reasoning), если модель их отдаёт;
- ответ модели санитизировать перед показом (разрешить только безопасные теги: `p`, `strong`,
  `em`, `ul`, `ol`, `li`, `a`, `code`), ссылки — только на домен платформы и доверенные домены.

## 5. Админка (для владельца платформы)
- Список диалогов с фильтром по клиенту и оценке.
- Отдельный список ответов с 👎 — по ним дописывать базу знаний.
- Счётчик вопросов и расход токенов за период.
- Кнопка «передать в поддержку»: создаёт тикет в платформе с историей диалога.

## 6. Этапы

1. **MVP:** виджет (окно, лента, ввод, стрим ответа), один эндпоинт, база знаний из markdown,
   полнотекстовый поиск, сохранение истории.
2. Оценки 👍/👎, админка с плохими ответами, лимиты запросов.
3. Контекст текущей страницы, ссылки-переходы на разделы, передача в поддержку тикетом.
4. Векторный поиск, мобильная полноэкранная версия, аналитика.

## 7. Критерии приёмки MVP
- Окно открывается/сворачивается, ширина меняется мышью и запоминается.
- Ответ идёт потоком, по-русски, без внутренних рассуждений модели и без сырого HTML.
- На вопрос из базы знаний — верный путь в интерфейсе; на вопрос вне базы — честное «не знаю»
  и предложение обратиться в поддержку.
- История диалога сохраняется между перезагрузками страницы.
- Ключ LLM не виден в браузере (проверить в DevTools → Network).

## 8. По правилам проекта

- Записать изменения в `docs/CHANGELOG.md` и поднять версию.
