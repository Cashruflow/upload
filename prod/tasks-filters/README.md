## Как это устроено

Разметка **не дублируется** и мобильная вёрстка не переписана. Те же самые узлы
(`#tt-tabs`, `#f-search`, `#search-row`, `#toolbar`, `#stats-bar`) физически
переносятся в панель функцией `fltLayout()` и только при совпадении
`matchMedia('(min-width:769px)')`; исходные позиции запоминаются в `FLT_HOME`
при загрузке и восстанавливаются при сужении окна. Поэтому ни один id, ни один
`onchange`, ни `renderStats()` про переезд не знают.

Порядок блоков внутри панели задаёт `order` в CSS, а не разметка — иначе перенос
туда-обратно менял бы мобильную раскладку.

## Стенд

Копия прод-стилей: `base.css` (правила из `tasks.html`), `theme.css`
(`btnCss()`+`inpCss()` на `THEME_DEFAULTS`, `ui_btn_force=1`), `flt.css` и
`flt.js` — дословные копии того, что ушло в прод.

```
npm i playwright
node shot.mjs     # ПК закрыта/открыта, вкладка Спринты, мобилка, resize туда-обратно
node before.mjs   # замер прежней раскладки
node modal.mjs    # карточка задачи должна быть НАД панелью
```

`shot.mjs` печатает метрики и кладёт скриншоты рядом. Что он проверяет:
позицию первой строки, число видимых строк, отсутствие горизонтальной прокрутки,
переезд поиска и вкладок в шапку, состав панели, чипы и счётчик на кнопке,
а на мобилке — что порядок блоков и `display` всех новых элементов не изменились.
